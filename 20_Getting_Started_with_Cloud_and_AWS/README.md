## 1단계 - 클라우드 및 AWS 소개 - 장점

#### 클라우드
인터넷을 통해 접근할 수 있는 서버, 소프트웨어, 데이터베이스 및 다양한 컴퓨팅 리소스의 네트워크

#### 클라우드 서비스
컴퓨팅 리소스 네트워크 임대 서비스
- 자본 비용을 가변 비용으로 바꿀 수 있다.
- 거대한 경제 규모로 혜택을 볼 수 있다.
- 데이터 센터가 필요 없다.

#### 클라우드 서비스의 장점
- 유연성: 필요에 따라 리소스를 확장하거나 축소할 수 있다.
- 비용 효율성: 사용한 만큼만 비용을 지불하는 모델을 제공.
- 접근성: 인터넷 연결만 있으면 어디서든 접근 가능.

#### 클라우드 서비스가 생기기 전에 발생하던 문제
- 낮은 인프라 가동률과 최대 부하에 대비한 인프라 마련
  - 클라우드가 없었을 때는 최대 부하를 예상하고 인프라를 마련할 수 밖에 없었다. ex) 구축 당시 고사양의 서버 NAS를 준비하는 등
  - 높은 비용을 지불하고 고사양의 인프라를 구축해도 서비스가 커지기 전까지 유휴 상태로 낭비되었다.
- 사전 계획 및 비용 필요
  - 최대 부하를 예측하는 일이 너무 어려웠다.
  - 인프라 유지 관리 팀이 필요했다.

#### 대표적인 클라우드 서비스 제공사
- AWS
- Azure 
- Google Cloud
- Oracle

## 3단계 - IAM 사용자 생성하기

나는 AWS 진행 실습을 하지 않기로 했다. (이미 프리티어가 끝났기 때문) 또한 AWS의 경우 UI가 복잡하고 자주 바뀌는 것을 경험하기도 했기 때문에 실습을 따라하기 보다는 각 단계의 주요 개념에 대해 노트하기로 했다.

#### IAM(Identity and Access Management) 사용자
AWS 계정 내에서 여러 개별 사용자를 생성하고 관리할 수 있게 해주는 서비스
- 개별 엔티티: 각 IAM 사용자는 AWS 내에서 고유한 개별 엔티티이다.
  - 독립적이며, 서로 다른 계정이라고 생각해도 된다.
- 단일 계정 연결: 각 IAM 사용자는 오직 하나의 AWS 계정에만 연결된다.
  - 서로 다른 AWS 계정에서 IAM을 공유하지 않는다.
- 개별 권한: 각 IAM 사용자는 자신만의 고유한 보안 자격 증명을 가진다.
- 비용 청구 : IAM 사용자가 이용한 서비스의 비용은 루트 계정에 청구된다.

#### IAM 사용 목적
AWS는 제대로 알고 사용하지 않으면 높은 금액의 청구서를 맞이할 수 있는 서비스이다. 사양에 따라 개인이 감당하기 부담스러운 비용이 청구되기도 한다.
- IAM을 분리하여 권한을 설정하고, IAM으로 서비스를 접근하여 루트 계정의 보안을 향상 시킨다. (루트 사용자의 권한은 절대적이므로 루트 사용자를 업무에 사용하는 것은 권장되지 않는다.)
  - IAM Key 등이 탈취 당하는 보안 이슈가 발생했을 때 계정 전체가 아닌 해당 IAM만을 조치하여 유연하게 대처할 수 있다. 
- 여러 명이 협업하는 경우 IAM을 통한 관리가 비용을 공동으로 처리할 수 있어 유용하다.

#### IAM 모범 사례
- 장기 보안 인증 정보가 있는 IAM 사용자 대신 임시 보안 인증을 사용하는 것이 권장된다.
- IAM 마다 최소한의 필요 권한만 설정하도록 하는 것이 권장된다.

#### IAM 그룹
- 그룹에 권한을 설정하고 해당 그룹에 IAM 사용자를 넣어서 권한 부여를 하는 방식으로 관리가 가능하다.
- 문제가 생긴 IAM의 경우 그룹에서 제외하면 되기 때문에 더 유연한 IAM 사용을 돕는다.

#### IAM 생성 실습
1. AWS 관리 콘솔에 로그인한다.
2. IAM 서비스로 이동한다.
3. 그룹 생성:
   - "사용자 그룹" 또는 "그룹" 섹션으로 이동한다.
   - "그룹 생성" 버튼을 클릭한다.
   - 그룹 이름을 입력한다.
   - 필요한 권한 정책을 선택한다.
     - 강의에서는 'AdministratorAccess'을 선택했다. (모든 서비스와 리소스에 대한 완전 접근 권한이며, 실제 프로덕트 환경에서는 사용에 주의해야 한다.)
   - 그룹 생성을 완료한다.
4. IAM 사용자 생성:
   - "사용자" 섹션으로 이동한다.
   - "사용자 추가" 버튼을 클릭한다.
   - 사용자 이름을 입력한다.
   - AWS 액세스 유형을 선택한다.
     - 프로그래밍 방식 액세스 : AWS API, CLI, SDK 및 기타 개발 도구를 사용하여 AWS 리소스에 프로그래밍 방식으로 접근 (Spring Boot 애플리케이션에서 접근하기 위해 필요하다.)
     - AWS Management Console 액세스 : 리소스 구성, 로그 확인, 문제 해결 등의 작업을 AWS 웹 인터페이스를 통해 수행 (모니터링 등의 기능이 필요할 경우)
   - 권한 설정:
     - "기존 그룹에 사용자 추가"를 선택한다.
     - "developers" 그룹을 체크한다.
     - 검토를 한 후 사용자 생성을 완료한다.
   - 생성된 사용자의 자격 증명 정보를 안전하게 저장한다.
     - AWS가 제공한 액세스 키 ID, 비밀 액세스 키가 있을 것이다. (노출되면 위험하다.)

IAM을 설정하는 이유는 IAM을 통해 Spring Boot 애플리케이션 코드로 AWS 리소스에 접근하기 위해서이다.
- 액세스 키 ID, 비밀 액세스 키가 필요하다.

## 4단계 - 리전 및 영역의 필요성 이해하기

#### 전통적인 방식의 애플리케이션 배포에서 발생할 수 있는 주요 문제
1. 긴 지연 시간 : 데이터센터가 한국에 있을 경우 지리적으로 멀리 떨어진 중동 지역의 사용자들은 긴 지연 시간을 경험하게 된다.
2. 낮은 가용성 : 만약 하나의 데이터센터를 운영한다면 데이터센터에 문제가 생겼을 경우 전체 서비스가 중단되며 이는 가용성을 떨어뜨리는 주요 요인이 된다.
3. 재해 복구의 어려움 : 특정 지역 전체가 영향을 받는 대규모 재해(예: 자연재해)가 발생할 경우, 해당 지역의 모든 데이터 센터가 영향을 받아 서비스 제공이 불가능해질 수 있다.
